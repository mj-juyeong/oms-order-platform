# OMS 알림 기능 도입 요약

- 작성일: 2026-06-01
- 목적: OMS 추가 기능 중 알림 기능의 필요성과 도입 방향을 발표용으로 간단히 정리한다.

---

## 1. 왜 알림 기능이 필요한가

OMS는 OIS 엑셀을 업로드한 뒤 파싱, 검증, 확정, 외부 API 제공, 라벨 다운로드까지 이어지는 운영 흐름을 가진다.

이 과정에서 운영자가 가장 놓치면 안 되는 것은 다음과 같다.

- 업로드 또는 파싱 실패
- 검증 Error 발생
- 확정 가능한 배치 방치
- 마감 시간 전 미확정 배치
- 외부 API 실패
- 라벨 다운로드 실패
- API Key 만료 예정

현재처럼 화면을 직접 들어가 확인하는 방식만 있으면 운영자는 여러 화면을 계속 확인해야 한다. 알림 기능은 이런 중요 이벤트를 한곳에 모아 보여주어, 운영자가 지금 처리해야 할 일을 빠르게 판단하도록 돕는다.

즉, 알림 기능의 목적은 단순한 메시지 표시가 아니라 **운영 누락 방지와 마감 리스크 조기 발견**이다.

---

## 2. OMS에서 알림이 필요한 주요 상황

| 상황 | 알림이 필요한 이유 | 기대 효과 |
|---|---|---|
| 검증 Error 발생 | 배치를 확정할 수 없는 상태를 즉시 알아야 함 | 오류 처리 지연 감소 |
| Warning 발생 | 확정 가능 여부를 운영자가 판단해야 함 | 검토 누락 방지 |
| 확정 가능 상태 | Error가 없는데 확정을 안 한 배치를 알려야 함 | 출고 준비 지연 감소 |
| 마감 임박 | 물류 운영은 마감 시간이 중요함 | 마감 전 선제 대응 |
| 외부 API 실패 | WOS/PL 연동 장애를 빨리 확인해야 함 | 연동 장애 대응 시간 단축 |
| 라벨 다운로드 실패 | 현장 출력 업무가 막힐 수 있음 | 출고 작업 지연 방지 |
| API Key 만료 예정 | 외부 연동이 갑자기 끊길 수 있음 | 장애 예방 |

---

## 3. 기능 도입 방향

알림 기능은 처음부터 복잡한 실시간 시스템으로 만들기보다, 운영에 바로 도움이 되는 범위부터 단계적으로 도입한다.

### 1단계: 인앱 알림 센터

OMS 화면 상단에 알림 아이콘을 추가하고, 주요 이벤트를 알림 목록으로 제공한다.

주요 기능:

- 미확인 알림 수 표시
- 최근 알림 목록 표시
- Error / Warning / Info 구분
- 알림 클릭 시 관련 화면으로 이동
- 읽음 처리

예시:

- 검증 Error 알림 클릭 → 검증 결과 화면으로 이동
- API 실패 알림 클릭 → API 로그 화면으로 이동
- 다운로드 실패 알림 클릭 → 다운로드 로그 화면으로 이동

### 2단계: 배치 상태 자동 갱신

업로드, 검증, 확정 같은 처리 상태가 바뀌면 화면을 새로고침하지 않아도 최신 상태를 확인할 수 있게 한다.

적용 화면:

- 대시보드
- 업로드 화면
- 배치 목록
- 배치 상세
- 검증 결과

초기에는 15~30초 간격의 자동 조회 방식으로 충분하다.

### 3단계: SLA / 마감시간 알림

운영 마감 시간이 확정되면 마감 전 미확정 배치나 Error 배치를 자동으로 알려준다.

예시:

- 마감 60분 전 미확정 배치 알림
- 마감 30분 전 Error 배치 알림
- 마감 초과 배치 Error 알림

이 기능은 배송일 기준, 마감 시간, 고객사별 기준을 운영 담당자와 확정한 뒤 적용한다.

현재 OMS 프로젝트 기준으로도 마감시간 알림은 도입 가치가 높다. OMS는 확정된 배치만 외부 API 제공과 라벨 다운로드 대상이 되기 때문에, 마감 전까지 배치가 미확정이거나 Error 상태로 남아 있으면 출고 준비와 외부 연동이 지연될 수 있다.

다만 현재 요구사항에는 "배송일/납기일 데이터"와 "배치 상태"는 준비되어 있지만, 실제 운영 마감 시간은 아직 확정되어 있지 않다. 따라서 1차 구현은 고정 마감 시간을 코드에 박아 넣기보다, 운영 정책이 정해진 뒤 고객사 또는 tenant별 마감 기준을 설정할 수 있게 두는 방식이 적합하다.

발표에서는 다음처럼 정리할 수 있다.

> 마감시간 알림은 OMS에서 확정 지연을 조기에 발견하기 위한 기능이다. 현재 시스템은 배송일과 배치 상태를 이미 관리하므로 적용 기반은 있으며, 운영 마감 시간만 확정되면 SLA 알림으로 확장할 수 있다.

### 4단계: 외부 채널 연동

인앱 알림이 안정화된 뒤, 필요하면 이메일이나 업무 메신저로 확장한다.

단, 모든 알림을 외부로 보내면 피로도가 높아지므로 아래처럼 중요 이벤트만 대상으로 한다.

- 마감 초과
- 외부 API 반복 실패
- 검증 Error 대량 발생
- API Key 만료 임박

---

## 4. 우선 적용할 알림 이벤트

| 우선순위 | 이벤트 | 설명 |
|---|---|---|
| 1 | 검증 Error 발생 | Error가 있으면 배치 확정 불가 |
| 2 | 배치 확정 가능 | Error 없이 검증 완료 |
| 3 | 외부 API 실패 | WOS/PL 연동 장애 감지 |
| 4 | 라벨 다운로드 실패 | 출력 업무 지연 방지 |
| 5 | 마감 임박 / 초과 | 출고 마감 리스크 관리 |
| 6 | API Key 만료 예정 | 외부 연동 장애 예방 |

---

## 5. 기대 효과

알림 기능을 도입하면 OMS는 단순 조회 시스템에서 운영자가 조치해야 할 일을 먼저 알려주는 시스템으로 발전한다.

기대 효과:

- 운영자가 여러 화면을 반복 확인하는 시간을 줄인다.
- 검증 오류와 미확정 배치를 빠르게 발견한다.
- 출고 마감 지연 가능성을 사전에 파악한다.
- 외부 API와 다운로드 실패를 놓치지 않는다.
- 장애 대응과 작업 추적이 쉬워진다.

결과적으로 알림 기능은 OMS의 핵심 목표인 **업로드 데이터의 안정적인 검증, 확정, 외부 제공**을 운영 관점에서 보완하는 기능이다.

---

## 6. 발표용 한 줄 정리

OMS 알림 기능은 운영자가 직접 찾아보지 않아도, 검증 오류·확정 지연·마감 위험·외부 연동 실패를 먼저 알려주는 운영 리스크 감지 기능이다.
