## 1. 제품 성격

OMS는 물류사가 OIS에서 생성된 목적별 엑셀 데이터를 업로드하고, 저장, 검증, 조회, 외부 API 제공, 라벨 다운로드까지 처리하는 운영자용 Admin/Backoffice 시스템이다.

이 제품은 마케팅 랜딩 페이지나 브랜드 홍보 사이트가 아니다. 화면의 목표는 물류 운영자가 짧은 시간 안에 대량 데이터를 확인하고, 필터링하고, 오류를 찾아 조치하고, 배치를 안전하게 확정하는 것이다.

주요 입력 데이터는 `Scan_upload_*`, `PL_EA`, `PL_Box`, `Label_EA`, `Label_Box` 시트이며, `Scan_upload_*`는 정식 입력 시트다. `Scan_upload_군량리`처럼 데이터가 0건인 시트도 정상 케이스로 표시해야 한다.

주문 조회 화면은 원본 주문 화면이 아니라 `PL_EA`, `PL_Box`를 기준으로 재구성한 OMS 조회용 주문 요약 데이터를 보여주는 화면이다.

## 2. 디자인 원칙

### 2-1. 업무 효율 중심

- 첫 화면부터 운영 상태, 배치 상태, 오류 수, 확정 가능 여부를 빠르게 파악할 수 있어야 한다.
- 장식적인 히어로, 과한 카드형 마케팅 구성, 큰 일러스트 중심 화면은 지양한다.
- 정보 밀도는 높게 유지하되, 운영자가 반복적으로 보기 쉬운 간격과 위계를 사용한다.

### 2-2. 긴 표 가독성

- 대량 행 조회를 전제로 고정 헤더, 정렬, 페이징, 가로 스크롤, 열 표시/숨김을 고려한다.
- 주문번호, 거래처코드, 품목코드, 바코드, QR코드 같은 문자열 코드는 숫자처럼 보이더라도 잘리거나 과학적 표기법처럼 축약되어 보이면 안 된다.
- 긴 코드 컬럼은 모노스페이스 또는 코드 친화적인 표시 스타일을 고려한다.
- 셀에는 원본값과 정규화값 확인 동선을 제공할 수 있어야 한다.

### 2-3. 빠른 필터링

- 배치, 고객사, 배송일, 상태, 시트명, 심각도, 상품코드, 거래처코드, 주문번호, 바코드/QR코드를 빠르게 조합 필터링할 수 있어야 한다.
- 자주 쓰는 필터는 상단 FilterBar에 고정하고, 고급 필터는 Drawer 또는 접이식 영역으로 분리한다.
- 필터 적용 상태는 칩 또는 요약 텍스트로 즉시 확인 가능해야 한다.

### 2-4. 상태와 심각도 구분

- 배치 상태는 전 화면에서 동일한 `BatchStatusBadge`로 표시한다.
- 검증 등급은 `SeverityBadge`로 Error, Warning, Info를 색상과 텍스트로 함께 구분한다.
- Error는 배치 확정을 차단하는 상태로 명확하게 보이게 한다.
- Warning과 Info는 조치 필요성과 참고 정보를 구분해 표시한다.

### 2-5. 업로드 흐름 가시화

다음 흐름이 배치 상세와 대시보드에서 자연스럽게 보이도록 구성한다.

```text
OIS 엑셀 업로드
  -> 시트 파싱
  -> 마스터 버전 적용
  -> 검증
  -> Error 조치
  -> 배치 확정
  -> 외부 API 제공 / 라벨 다운로드
```

확정되지 않은 배치는 외부 API 응답 및 운영 다운로드 대상에서 제외된다는 점을 UI에서 분명히 드러낸다.

### 2-6. 확인 필요 정책 분리

요구사항에 아직 확정되지 않은 항목은 UI에서 확정 정책처럼 보이지 않게 표현한다.

- 차수별 주문 조회/다운로드는 MVP 필수 화면이 아니라 추후 구현 항목이다.
- `장지`, `군량리`의 화면 용어는 센터/거점/노선/버스 중 운영 확인이 필요하다.
- Warning이 남아 있어도 확정을 허용할지 여부는 운영 정책 확인이 필요하다.
- 라벨 다운로드 컬럼 순서와 시트명 유지 정책은 확인 필요 항목이다.

## 3. 주요 사용자

| 사용자 | 주요 목적 | 주요 권한 관점 |
|---|---|---|
| 물류 운영자 | OIS 엑셀 업로드, 검증 실행, 오류 확인, 배치 확정, 라벨 다운로드 | `OPERATOR` |

## 5. MVP 우선 디자인 대상

다음 화면을 1차 디자인 시안 제작 대상으로 지정한다.

1. 대시보드
2. OIS 엑셀 업로드
3. 배치 목록
4. 배치 상세
5. 검증 결과
6. 주문 조회
7. 상품 마스터
8. 배송지/차량 마스터
9. 라벨 다운로드

Scan 조회, PL 조회, Label 조회, 이력/로그 조회는 공통 DataTable 패턴 확장 화면으로 후속 시안에서 다룬다.

## 6. 공통 Layout 제안

### 6-1. 전체 구조

```text
Sidebar
  + Header
    + Breadcrumb
    + Page title / primary action
    + FilterBar
    + Content area
      + MetricCard / Status summary
      + DataTable
      + Drawer or Modal
      + Toast / Alert
```

### 6-2. Sidebar

- 좌측 고정 내비게이션을 기본으로 한다.
- 메뉴 그룹:
  - 대시보드
  - 업로드/배치
  - 조회: 주문, Scan, PL, Label
  - 다운로드
  - 마스터
  - 이력/로그
  - 관리자
- 현재 위치는 명확한 선택 상태로 표시한다.
- 권한에 따라 메뉴 노출 여부가 달라질 수 있음을 고려한다.

### 6-3. Header

- 현재 tenant/client 컨텍스트, 사용자명, 역할, 로그아웃 진입점을 표시한다.
- 운영자가 고객사 범위를 자주 전환해야 할 수 있으므로 client 선택 UI 영역을 고려한다.
- 전역 알림 또는 최근 실패 작업 알림 영역을 둘 수 있다.

### 6-4. Breadcrumb

- 배치 상세, 검증 결과, 마스터 버전 상세처럼 깊이가 있는 화면에 사용한다.
- 예: `배치 > 배치 목록 > BATCH-20260528-001 > 검증 결과`

### 6-5. Page title

- 화면명, 짧은 설명, 주요 액션 버튼을 한 줄에 구성한다.
- 예: `배치 상세` + `재검증`, `확정`, `취소` 액션.

### 6-6. FilterBar

- 배송일, 고객사, 배치 상태, 검증 등급, 시트명, 코드 검색 등 핵심 필터를 제공한다.
- 운영 화면에서는 검색어 입력, 날짜 범위, select, checkbox, reset 버튼을 일관되게 사용한다.
- 고급 필터는 펼침 영역 또는 Drawer로 둔다.

### 6-7. DataTable

- 고정 헤더, 정렬, 페이징, 가로 스크롤을 기본 고려한다.
- 첫 열에는 상세 진입 또는 선택 checkbox를 둘 수 있다.
- 긴 코드 컬럼은 줄바꿈보다 가로 스크롤과 복사 가능한 표시가 적합하다.
- 행 클릭 시 Drawer로 행 상세를 열 수 있다.

### 6-8. Status badge

- 배치 상태, 다운로드 상태, 마스터 버전 상태는 같은 계열의 Badge로 통일한다.
- 권장 상태 예시:
  - `UPLOADED`
  - `PARSING`
  - `PARSED`
  - `VALIDATING`
  - `VALIDATED`
  - `CONFIRMED`
  - `CANCELLED`
  - `ROLLED_BACK`
  - `FAILED`

### 6-9. Severity badge

- `ERROR`: 확정 차단, 붉은 계열
- `WARNING`: 운영 확인 필요, 노란/주황 계열
- `INFO`: 참고, 파란/회색 계열

색상만으로 구분하지 않고 텍스트 라벨을 함께 표시한다.

### 6-10. Drawer 또는 Modal

- Drawer: 행 상세, 원본값/정규화값 비교, 검증 오류 상세, 배치 메타정보 확인.
- Modal: 확정, 취소, 롤백, 마스터 활성화처럼 의사결정이 필요한 작업.

### 6-11. Toast/Alert

- Toast: 업로드 시작, 검증 완료, 다운로드 요청 완료 같은 일시적 피드백.
- Alert: Error 존재로 확정 불가, API 제공 제외 상태, 마스터 미선택처럼 화면 상단에서 유지해야 하는 경고.

## 7. 화면별 와이어프레임 설명

### 7-1. 로그인

| 항목 | 내용 |
|---|---|
| 목적 | OMS 내부 사용자 인증 |
| 주요 액션 | 로그인, 비밀번호 입력 표시 전환 |
| 주요 필터 | 없음 |
| 주요 테이블 컬럼 | 없음 |
| 빈 상태 | 첫 접속 상태에서는 로그인 폼만 표시 |
| 오류 상태 | 잘못된 계정/비밀번호, 비활성 사용자, 세션 만료 안내 |
| 권한 고려사항 | 인증 전 `PUBLIC`; 로그인 후 역할별 메뉴와 액션 제한 |

와이어프레임 메모:

- 화면 중앙에 단순한 로그인 폼을 배치한다.
- 배경은 과한 이미지 없이 흰색/회색 기반으로 정돈한다.
- 로그인 후 이동 대상은 대시보드 또는 최근 사용 화면으로 고려한다.

### 7-2. 대시보드

| 항목 | 내용 |
|---|---|
| 목적 | 오늘 또는 선택 기간의 배치 상태, 오류 현황, 확정 가능 상태를 빠르게 파악 |
| 주요 액션 | 배치 상세 이동, 검증 결과 이동, 업로드 화면 이동 |
| 주요 필터 | 고객사, 배송일/기간, 배치 상태 |
| 주요 테이블 컬럼 | 배치번호, 고객사, 배송일, 상태, Error 수, Warning 수, 업로드자, 업로드시각, 확정시각 |
| 빈 상태 | 선택 기간에 업로드 배치가 없음을 표시하고 업로드 화면 진입 제공 |
| 오류 상태 | 데이터 로딩 실패, 집계 실패, 권한 없음 |
| 권한 고려사항 | `VIEWER`는 조회만, `OPERATOR` 이상은 업로드/검증/확정 진입 가능 |

와이어프레임 메모:

- 상단에는 MetricCard 4~6개를 배치한다.
- 추천 지표: 오늘 업로드 배치, 확정 완료, Error 배치, Warning 배치, 다운로드 가능 배치, API 제공 가능 배치.
- 하단에는 최근 배치 테이블과 오류 상위 유형 요약을 배치한다.
- 차수별 대시보드는 MVP가 아니므로 별도 강조하지 않는다.

### 7-3. OIS 엑셀 업로드

| 항목 | 내용 |
|---|---|
| 목적 | OIS 생성 XLSM 파일을 업로드하고 배치를 생성 |
| 주요 액션 | 파일 선택/드롭, 고객사 선택, 마스터 버전 선택, 업로드 시작, 업로드 취소 |
| 주요 필터 | 없음. 단, 업로드 컨텍스트로 고객사와 마스터 버전 선택 |
| 주요 테이블 컬럼 | 업로드 후 시트명, 시트유형, 데이터 행 수, 상태, 메시지 |
| 빈 상태 | 파일 드롭존과 업로드 전 안내 표시 |
| 오류 상태 | 확장자 오류, 파일 크기 초과, 필수 시트 없음, 파싱 실패, 마스터 버전 없음 |
| 권한 고려사항 | `OPERATOR`, `ADMIN` 가능. `VIEWER`는 접근 제한 또는 읽기 전용 |

와이어프레임 메모:

- 상단에 업로드 단계 표시: 파일 선택, 시트 인식, 검증 대기.
- Dropzone에는 허용 파일을 XLSM 중심으로 표시하되 매크로 실행이 아니라 데이터 읽기만 수행한다는 표현은 내부 안내 수준으로 짧게 둔다.
- 업로드 완료 후 `배치 상세로 이동`, `검증 결과 보기` 액션을 제공한다.
- `Scan_upload_군량리` 0건은 실패가 아니라 정상 시트로 표시할 수 있어야 한다.

## 9. 디자인 톤

OMS는 물류/운영/관리자 시스템에 맞는 차분한 톤을 사용한다.

### 9-1. 기본 톤

- 흰색/회색 기반의 밝고 정돈된 배경
- 표와 필터가 주인공인 밀도 있는 업무형 레이아웃
- 과한 그라데이션, 큰 장식 이미지, 마케팅형 카피는 사용하지 않는다.
- 카드 반경은 작게 유지하고, 섹션 전체를 과도하게 카드화하지 않는다.

### 9-2. 상태 색상 방향

실제 Tailwind 컬러 토큰은 구현 단계에서 확정한다. 디자인 시안에서는 다음 의미만 유지한다.

| 상태 | 색상 방향 | 의미 |
|---|---|---|
| Error | 붉은 계열 | 배치 확정 차단, 즉시 조치 필요 |
| Warning | 노란/주황 계열 | 운영 확인 필요 |
| Info | 파란/회색 계열 | 참고 또는 안내 |
| Success/Confirmed | 초록 계열 | 확정, 정상 완료 |
| Neutral | 회색 계열 | 대기, 취소, 비활성, 일반 정보 |

### 9-3. 타이포그래피와 표기

- 화면 제목은 명확하고 짧게 둔다.
- 표 컬럼명은 업무 용어를 우선한다.
- 영문 상태값은 Badge 안에서 한국어 라벨 병기를 고려한다.
- 긴 코드와 식별자는 말줄임 처리만 하지 말고 복사 또는 전체 보기 동선을 제공한다.
